GroupMate 的运行状态和终态回执共用有界 Redis 命名空间，业务记忆使用独立 SQLite 存储。

运行状态最多同时保留 16 个检查点。终态回执最多保留 4096 条，每条最长保留 24 小时，供重复投递、重试和终态核对使用；容量不足时不会提前删除尚未过期的回执。运行状态、事件、回执和引用的总逻辑容量保持 8 MiB。

创建检查点时原子预留一个终态回执位置。所有状态写入还为当前检查点预留最多 4 KiB 的终态空间，防止模型已经生成回答后才发现无法保存终态。没有可用位置或容量时，在接纳新请求前返回资源限制结果。此限制无需配置，也不改变已有 Redis 数据格式或回执有效期。

提高回执条数上限用于避免正常一天超过 128 次回复后持续失败；总字节上限继续约束实际内存占用。到期回执由 Redis TTL 清理，过期造成的容量统计漂移由运行状态存储进行有界校正。
