群记忆保存当前群的规则、共同偏好、稳定文化和群体事实。群管理员直接执行保存或修改命令，普通成员可以查看和在普通聊天中召回；完整导出和删除全部由群主执行。每次操作重新查询当前成员角色，消息里的旧角色不会授予权限。

群记忆和群文化在所有群默认开启，无需配置群号或执行开启命令；只有群管理员或群主手动关闭才停止：

- `#群记忆 状态`：查看当前群的群记忆与群文化开关。
- `#群记忆 关闭` / `#群记忆 开启`：停止或恢复当前群的群记忆注入、召回和新记录。
- `#群文化 关闭` / `#群文化 开启`：只停止或恢复群文化分类描述；群记忆关闭时群文化同样不生效。

开关每次都重新核验当前管理员角色，关闭状态独立持久化，跨重启、删除全部和机器人重新入群都保留。关闭后不再注入对话或接受保存、更正、续期，进行中的任务依赖的群记忆会失效；已有内容仍可列表、遗忘、导出和由群主删除全部，不会被自动删除。重新开启会推进开关代次，关闭前已建立的资料依赖不能恢复。

- `#群记忆 列表 [页码]`
- `#群记忆 记住 规则 本群禁止刷屏`
- `#群记忆 记住 共同偏好 本群共同偏好是周末读科幻小说`
- `#群记忆 记住 文化 本群每周末分享阅读心得`
- `#群记忆 记住 群体事实 本群成立于2020年`
- `#群记忆 更正 @编号 本群禁止重复刷屏`
- `#群记忆 续期 @编号 [天数]`
- `#群记忆 遗忘 @编号`
- `#群记忆 导出`（群主在群内发起，文件私发本人）
- `#群记忆 删除全部 确认`（群主）
- `#群记忆 候选`、`#群记忆 通过 @编号`、`#群记忆 拒绝 @编号`（群管理员，审核自动候选）

## 自动候选

长期记忆为影子或自动模式时，机器人会从普通群聊中发现关于本群整体的稳定信息，生成待审核候选。候选不会自动保存，也不参与召回；当前群管理员通过后才成为群记忆或群文化。模型生成的候选不代表群共识。

- **收什么**：群规则、全群共同偏好、语言约定、梗说明、群体事实（如成立时间、群主题）。须由至少两名成员的发言支持，或由管理员以本群名义宣布；文本须以“本群”开头，并通过与 `#群记忆 记住` 相同的检查。
- **不收什么**：成员个人信息、经历和关系，单人观点，玩笑、反问和假设，今天/明天/本周之类的临时安排；引用、转发、图片和媒体、`#` 命令、凭据类内容不进入抽取，机器人自己的消息也不进入。
- **频率与成本**：每群攒够 20 条纯文字消息、至少 2 人发言才抽取一次，同群至少间隔 30 分钟、每天最多 3 次，全部群每天合计最多 30 次（北京时间按日计数，重启后计数重置）。每次抽取是一次独立模型调用：禁用工具、思考和图片，发言人只以匿名编号出现，不发送 QQ 号、昵称或群名，最多输出 512 Token；日志事件 `groupmate.group_memory.learning` 单独记录阶段、候选数、Token 和参考费用，不记录消息正文或身份。
- **上界**：内存中最多缓冲 32 个群、每群 20 条消息，排队批次最多 4 个，单 worker 依次处理、每批限时 30 秒，没有常驻轮询；每次最多 3 条候选，每群最多 8 条未审核自动候选，达到上限后该群暂停抽取。候选 7 天未审核即过期，由原有维护批次清理。
- **去重和冲突**：与有效群记忆或约 37 天内的任何候选（含已拒绝、已过期，超过后由维护批次清除）相同的内容不再提交；与已有同类记录相近或同一文化类别已有描述时，候选标注“与已有记录相近”并保持待审核，通过时不会覆盖旧记录，文化类别仍需先更正或遗忘旧描述。
- **审核**：`#群记忆 候选` 列出规则、共同偏好、群体事实类候选，`#群文化 候选` 列出分类文化候选，`[自动]` 表示来自群聊、`[成员提议]` 表示成员手动提议。审核每次重新核验当前管理员角色；自动规则类候选任一当前管理员可通过，分类文化候选仍需发言证据以外的另一位管理员。机器人不会主动提醒新候选，避免在群里刷屏；管理员按需查看。
- **开关**：群管理员 `#群记忆 关闭` 后该群不再生成任何自动候选，`#群文化 关闭` 后不再生成文化类候选；机器人主人可在锅巴“群记忆自动候选”（`groupMemoryLearningEnabled`，默认开启、即时生效）整体关闭。关闭不会删除已有候选，管理员仍可审核或拒绝。

本阶段采用保守的群体陈述范围，每条最多 800 UTF-8 字节，不保存个人身份、敏感信息、私聊、第三方转述或引用。个人自动记忆仍按本人参与状态独立运行；群规则不会因为个人记忆开启而获得管理权限。

群记忆与个人记忆复用 SQLite canonical 存储、FTS5 词法索引和 Context Planner。群号、机器人账号和机器人当前入群时间构成硬隔离；机器人离群再加入后，新的生命周期不能读取旧记录。检索先按 namespace 过滤，再综合关键词、时间、置信度和来源排序；没有启用外部向量服务。记忆作为带来源的不可信资料进入上下文，不能提供工具或系统权限。

遗忘会立即阻止召回。删除全部还会按有界批次清理正文、索引和 SQLite 残留；未完成时显示待清理，启动会恢复。长期记忆操作不删除独立诊断日志或已经送达的导出文件，日志继续按其独立保留策略清理。

启动和每分钟的单个有界维护批次会处理到期候选、超过保留宽限期的正文，以及过期 tombstone、审计、命令和导出预留。每批最多检查 4 个 namespace，每个操作最多处理 32 条，轮转检查全部 namespace；空闲库不写新账本。维护失败不会改变 QQ 回复，锅巴显示保留清理状态和上次处理条数。

`apps/memory.js` 仅保留 Yunzai 插件发现与文件送达接口；实现以 `src/runtime/GroupMemory.ts` 为唯一来源，由本地 TypeScript 构建生成 `dist/`，远端无需编译。


群文化提案默认开启，可使用：

- `#群文化 提议 主题偏好 本群偏好讨论天文`
- `#群文化 提议 语言约定 本群使用简短句子`
- `#群文化 提议 梗说明 本群使用星球梗`
- 管理员用 `#群文化 候选` 查看，再用 `#群文化 通过 @编号` 或 `#群文化 拒绝 @编号` 审核。审核者必须是另一人，且当前仍有管理员权限。
- `#群文化 列表` 查看已保存描述；`更正 @编号 <新内容>`、`续期 @编号 [天数]`、`遗忘 @编号` 管理它们。分类描述的更正需保留列表中的 `本群主题偏好：`、`本群语言约定：` 或 `本群梗说明：` 前缀。

提案仅接受当前发言的纯文字，拒绝引用、转发、媒体、凭据及个人敏感信息。待审提案不参与召回；同类别已有有效描述时，新提案保持待审，需明确更正或遗忘旧内容。审核只表示允许保存描述，不证明全群共识，也不产生群规则或工具权限。主题、语言、梗的初始有效期分别为30、90、14天，每群最多64条文化和32条待审文化候选，另受原记忆总容量约束。

`#群文化 关闭` 会停止新分类描述的提案和召回，并撤销运行中相关资料依赖；不会删除 canonical 内容。原 `personalMemoryGroupAllowlist`、`groupCultureGroups` 配置已移除，真实配置中残留的旧值不再生效。既有 `#群记忆 记住 文化/共同偏好` 行为保留，既有描述同样不代表共识。分类文化复用现有 canonical、来源、审批证据、revision、遗忘、群主导出/删除与生命周期隔离，schema v3 和个人/群记忆接口保持兼容；除上文的自动候选抽取外，不运行额外模型提取、媒体收集或向量服务。
