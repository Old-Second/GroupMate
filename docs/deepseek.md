# DeepSeek 适配与参考费用

GroupMate 使用自有 OpenAI-compatible Chat Completions 适配器。推荐模型名为 `deepseek-flash`；官方仍接受的 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 按 Flash 能力和价格处理。真实配置不会被自动改写。Pro 不支持图像输入。

根据 2026-10-21 复核的[官方文档](https://api-docs.deepseek.com/zh-cn/)，上下文与最大输出分别为 1,048,576 和 393,216 Token。运行时按模型声明窗口派生请求预算（`apiContextWindowTokens` 可显式覆盖，上限 16,777,216），但仍与请求体字节上限取小：一次 1M Token 请求约 4 MiB，硬上限为 16 MiB 请求体、8 MiB 协议链和 12 MiB 检查点。官方请求体上限为 48 MiB，这里取更小的值是为远端内存留余量。`apiMaxToken` 与深度求索 Profile 的输出上限同为 393,216；默认 4,096 适合群聊。文本估算采用两倍校准余量；它仍是启发式估算，费用只使用响应中的实际用量。官方给出的估算口径是中文约 0.6 Token/字、英文约 0.3 Token/字符，插件用 UTF-8 字节 / 4 估算并在规划器再乘 2 倍余量，因此对中文偏保守、对纯英文仍有余量。

思考模式使用 `thinking`，`medium` 与 `xhigh` 映射为 `high`，`ultra` 映射为 `max`（官方映射为 `minimal→low`、`low→low`、`medium→high`、`high→high`、`xhigh→high`、`max→max`、`ultra→max`）。思考时忽略温度、将 `top_p` 限制为 0.95–1；非思考时忽略 `top_p`。思考模式不能强制 `tool_choice=required`。官方文档规定：请求携带 `tools` 时，历史轮次的完整 `reasoning_content` 必须回传，缺失会返回 400；不带 `tools` 时该字段会被忽略、不进入上下文。插件因此把 `reasoning_content` 存进独立的协议状态随会话持久化，展示层截断不会代替回传。旧历史缺失的思考不能恢复，仅以空状态兼容。默认使用带来源、明确遗漏的确定性节选摘要；可在显式试点群启用[历史原文证据摘要](conversation-summary.md)，额外请求共享预算，不改写事实。

公开的 `/models` API 提供能力元数据，`/user/balance` 仅提供账户余额；没有逐请求实扣金额、账单时间或实时单价接口。共享账户的余额差也不能精确归属某个请求。

工具调用按官方 Chat Completions 示例执行：assistant 的 `tool_calls` 后紧跟与 `tool_call_id` 匹配的 `tool` 消息，再发下一次请求，工具参数文本原样重放以保持前缀稳定；官方说明该接口不支持在对话中间插入新的工具调用，插件只回放已经发生过的工具轮，不在历史中间注入工具调用或 `system` 消息。图像只允许出现在 `user` 消息中，`system` 或 `assistant` 携带图像会被判 400；官方按尺寸把图片折算成 Token（进入模型前缩放到约 1300×1300 以内、单图上限 1,024 Token、单请求最多 600 张），插件使用 `detail=low`（约 512×512）并只接受宿主图片外链、不内联 base64，因此请求体远低于官方 48 MiB 与单图 32 MiB 的限制。官方 Files API（单文件 64 MiB、有效期 1 小时至 30 天、单账号 25 GiB）适合反复引用同一张大图；当前插件不重复上传图片字节，历史图片走宿主链接续签，所以不启用 Files API。错误码按官方表映射：400 视为请求错误并尝试一次性丢弃可选上下文，401/403 鉴权失败、402 余额不足、422 参数错误不可重试，429 限流与 500/503 服务不可用可重试。

提示前缀决定缓存命中。官方文档把缓存描述为「缓存前缀单元」：请求结束处（用户输入结束、模型输出结束）、多次请求的公共前缀、以及长输入/长输出中的固定 Token 间隔都会落盘独立单元，只有完整匹配某个单元才计命中，部分匹配不计；未再使用的缓存由供应商在数小时到数天后清除，构建耗时秒级，且是尽力而为、不保证命中。命中和未命中由响应的 `usage.prompt_cache_hit_tokens`、`usage.prompt_cache_miss_tokens` 分别报告，两者之和必须等于 `prompt_tokens`，费用按这两个数加输出 Token 计价。供应商没有查询缓存状态的接口，插件只能用会话空闲时长估算前缀是否已冷（`contextPrefixCacheIdleMinutes`，默认 360 分钟，对应官方「数小时」档）。在这个模型下，系统指令保持常量；会每轮变化的会话元数据放在当前请求之前；群聊窗口按消息身份选取锚点，连续轮次只在末尾追加。会话历史不按固定对话条数裁剪，而是按请求的可用输入 Token 预算压缩：历史达到 `contextCompactionTriggerPercent`（默认 65%）时，把较早内容折叠为持久摘要，保留 `contextCompactionKeepPercent`（默认 35%）的最近原文，因此提示开头稳定为「系统指令 + `[user: 历史摘要]` + `[assistant: 已确认摘要]` + 最近原文轮次」。折叠只发生在越过高水位的那一轮（或会话空闲超过 `contextPrefixCacheIdleMinutes`、供应商前缀缓存已失效因而重写无额外损失且至少能回收 `contextCompactionMinReclaimTokens` 的轮次），折叠之间前缀逐字节不变；折叠后保留的最早条目必须是用户消息，避免恢复没有对应提问的答复。摘要为确定性节选、不使用额外模型请求，单条保留首尾原文并明确标记省略，总量由 `contextCompactionSummaryMaxChars`（默认 2400 字符）约束；更早的细节会逐步缩短或省略，但不会整轮丢弃。关闭 `contextCompactionEnabled` 后历史按原文保留，直到 16,384 条 / 16 MiB 的会话状态硬上限和 16,384 个上下文条目 / 16 MiB 的请求硬上限；这些只是安全边界，不构成日常对话轮数上限。放大窗口会同步放大 Redis 会话与检查点占用，部署前应结合远端内存评估。

参考费用按每次成功响应的缓存命中、未命中、输出 Token 分别乘以官方单价，使用整数计算后累计。输出用量已包含思考 Token，不再重复收费。

| 每百万 Token（元） | Flash 空闲 / 高峰 | Pro 空闲 / 高峰 |
| --- | --- | --- |
| 输入缓存命中 | 0.02 / 0.04 | 0.15 / 0.30 |
| 输入缓存未命中 | 1 / 2 | 4.5 / 9 |
| 输出 | 4 / 8 | 13.5 / 27 |

高峰为北京时间周一至周五 09:00–12:00、14:00–18:00，排除中国法定节假日；周末即使调休上班仍为空闲。2026 年日历依据[国务院通知](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)。跨峰谷边界的请求按较高单价显示上限；没有完整缓存明细时，输入全部按未命中计算上限。缺少用量、报价或日历依据显示“不可用”，不显示零费用。

报价为核验日的版本化目录，不是供应商账单。旧 checkpoint 的价格快照不被改写；新请求按当时目录独立累计。目录在 2026-11-09 进入待复核状态，费用停止显示而模型能力仍有效；发布新目录前须复核官方价格和节假日日历。不能用今天的价格重算未知历史消费。

独立 JSONL 日志增加 `model.resolution`、`context.planned`、`tool.network`，分别记录能力/报价状态、每轮来源选择与压缩计划、网络阶段和耗时；不写入凭据、网络地址或配置对象。诊断失败仍不影响聊天与 QQ 投递。
